# T32 address formation and data

## Address formation, literal data, and control transfer

[Every halfword that forms an address from the execution position or stack pointer.english](../../arm/thumb/Every%20halfword%20that%20forms%20an%20address%20from%20the%20execution%20position%20or%20stack%20pointer.english) classifies **all 4,096 two-byte Thumb halfwords from A000 to AFFF**: 2,048 `ADR` T1 instructions which calculate `Align(instruction address + 4, 4) + 4 * unsigned imm8`, and 2,048 `ADD Rd, SP, #immediate` T1 instructions which compute `SP + 4 * unsigned imm8` into R0–R7 **without changing SP**. Their [complete 4,096-row table](../fixtures/armv7-a-t32-address-generation-halfwords.tsv) records registers, immediates and computed addresses for two illustrative starting instruction locations.

[Every PC-relative data-word load halfword.english](../../arm/thumb/Every%20PC-relative%20data-word%20load%20halfword.english) classifies **all 2,048 halfwords from 4800 to 4FFF**. This distinct `LDR (literal)` T1 instruction calculates an aligned PC-relative address, then actually **reads a 32-bit data word from memory**. That read has separate mapping, permissions and fault requirements. Its [complete 2,048-row encoding table](../fixtures/armv7-a-t32-pc-relative-word-load-halfwords.tsv) is not a proof that the reads were ever executed.

[An address a load and a branch disagree about the same bytes.english](../../arm/thumb/listings/An%20address%20a%20load%20and%20a%20branch%20disagree%20about%20the%20same%20bytes.english) starts from **sixteen real assembled bytes**. It specifies a PC-derived address, a literal word load, and a branch around both `BKPT` and four literal-data bytes before stopping at ungranted `SVC`. The independent linear disassembler prints those literal bytes as plausible `LDRSB` and `ASRS` instructions; those are not instructions the selected execution-index path actually executes. This is direct evidence why the language must distinguish **decoded bytes**, **data reads**, and **executed instructions**.

[The address/data diagnostic receipt](../evidence/2026-10-11-PC-relative-address-and-data-load-audit.english) records the actual foreign clang/LLVM 17 assembler/decoder and object hashes, **4,096** address-generation and **2,048** literal-load classification checks, and a deliberately retained diagnostic formatting failure (decimal versus hexadecimal immediate text) that was corrected before the complete literal-load comparison passed. No claim is made about ICK/NDK execution or an independent compiler acceptance check.

The previously completed five decoding regions accounted for 6,912 distinct two-byte halfword values. Adding the two disjoint A000–AFFF and 4800–4FFF regions yields **13,056 classified sixteen-bit halfword values** in seven closed decoder subtrees. The permitted long-named operation set now has **73 entries**: existing operations 40 and 41 were made encoding-precise, and new operation 73 names SP-relative address formation without changing SP. This remains a partial ARMv7-A T32 ISA specification, not a working frontend or verified physical-machine execution.

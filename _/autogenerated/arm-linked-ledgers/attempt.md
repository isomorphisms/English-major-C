# Linked ARM ledger generator

## Purpose and types

Add preliminary English descriptions for the two already captured linked ARM
listings, without changing the frozen six-tree inventory or running QR code.

specimen : pinned Git commit × binary path × listing path × ABI
native_record : section × address × memory bytes × ISA × original assembly
ledger_entry : native_record × preliminary English × semantic_status
describe : native_record → preliminary_description | missing_description
account : specimen → List ledger_entry → exact_alignment | missing_evidence

Exact bytes and record order are invariants. DATA and suppressed byte ranges
are disjoint from instructions. The width comes from each encoding. Linked
occurrences do not increase the frozen native denominator. Translation is not
semantic certification. Files, Git blob reads, SHA-256, TSV, and diagnostics are
effects; description selection and interval arithmetic are pure operations.

## Fallback boundary

The bounded Node generator extends the existing read-only inventory approach;
it may import the existing ELF/listing reader. The independent ai-ci verifier
must not import this producer or use its generated crosswalk as ground truth.
Neither program compiles, loads, or invokes a specimen.

## Removal acceptance

The first blocker is a bootstrapped direct-host Idriç compiler. Once available,
typecheck this choice model, then port one exact native/ledger alignment check;
an intact specimen must pass and a dropped or modified record must fail.

# EMC-2 — the archived softfp QR objects actually execute

**Executed under QEMU Linux ARM; one numerical sample passes.** This package
links the three exact original objects from the parent A32/softfp archive.
It does not replace them with the separate hardfp specimens. The five needed
BLAS bodies are independently identified reference sources compiled with the
same softfp convention and linked into the saved ELF.

The six-point sample produces rank **2**, intercept **17/21**, slope **33/35**
and squared vertical residual sum **134/105**, to the stated floating tolerance.
The independent verifier explicitly rejects NaN and infinity; the original C
caller's tolerance comparisons alone would not reject a NaN coefficient.

## Identity and provenance

The [parent original-object ledger](../SHA256SUMS) is unchanged. The linked
executable SHA-256 is
`bfb8e71c45d914fa698dfb2e6371f2c391392dde72ce8e5cf0fc5e6716759170`.
[capture-environment.txt](capture-environment.txt) records original-object
identities, compiler and runtime versions, actual ELF attributes, linked symbol
addresses and QEMU options. [SHA256SUMS](SHA256SUMS) identifies all 16 captured
files. This ledger does not include its own digest or the explanatory README.

Reference BLAS source is
[Reference-LAPACK/lapack at `0ac327b5e0b3586a87a2b25e50bbc570f20702d0`](https://github.com/Reference-LAPACK/lapack/tree/0ac327b5e0b3586a87a2b25e50bbc570f20702d0/BLAS/SRC).
The five source files and compiled objects are preserved in `reference-blas/`
with the unmodified upstream license. R-derived QR inputs retain their original
R/GPL provenance. The new BLAS implementation is not asserted to be the
historical x86 executable's original shared-library implementation.

GNU Fortran 14.2.0 recompiled the original QR sources as a reproducibility
check. All three unlinked `.text` sections are byte-identical to the originals;
debug paths can differ, so no claim of complete rebuilt-object identity is made.
The saved executable consumed the original archived objects, not those fresh
reproductions. The verifier additionally compares **4,496 unrelocated bytes**
in the linked QR routines against the original object payloads. It excludes
43 four-byte relocation sites, whose final values are visible in the linked
disassembly; it does not mistake unchanged bytes for a complete relocation proof.

## Inspectable files

| File | Evidence |
| --- | --- |
| `call_r_qr.armv7-softfp` | Saved Linux ARM ELF32 executable, A32 QR routines, softfp argument ABI |

| `qr-instruction-state.trace.txt.gz` | QEMU pre-instruction integer/VFP registers and status, compressed without a timestamp |
| `reference-blas/` | Exactly five foreign BLAS sources, compiled objects and license |

The trace uses QEMU 8.2.2 `-one-insn-per-tb`, CPU model `cortex-a7` and
`-d in_asm,cpu,fpu,nochain`, filtered to the three QR symbol intervals. It has
**994 pre-instruction states at 734 distinct addresses**: 475 in `dqrdc2`,
80 in `dqrls`, and 439 in `dqrsl`. Repeated addresses are repeated execution,
not extra static instructions. QEMU's `IN` disassembly blocks describe translated
blocks; the CPU state rows identify the observed visits. On this QEMU build,
`OBJD-T` prints raw target bytes instead of a mnemonic; the independent GNU
listing supplies their decoding.

For the first observed QR instruction, the execution index is `0x10f54`,
RSP is `0x407ff710`, LR is `0x105e8` and FPSCR is zero. A32 word `e92d4ff0`
saves R4..R11 and LR, nine four-byte words. The next observed state has
execution index `0x10f58` and RSP `0x407ff6ec`, exactly 36 bytes lower. This is
an observed register transition; the trace does not dump the nine saved memory
words. It is not an exhaustive memory-state proof.

## Verification and limits

[verify-softfp-execution.mjs](../../../autogenerated/arm-qr-softfp-execution/verify-softfp-execution.mjs)
checks artifact identities, independently re-decodes the linked ELF, compares
unrelocated original QR bytes, validates the finite rational numerical oracle,
and reruns both numerical execution and the bounded instruction-state trace.
Negative fixtures reject altered bytes/digests, NaN, infinity, a wrong or missing
coefficient, and an absent trace. Its narrow Node fallback and the failed
canonical Idriç check are documented beside it. Workflow presence alone is not
a passing exact-head run.

This result is Linux ARM emulation of the identified GNU specimens. The
separate hardfp experiment remains a different ABI and artifact. Dynamic libc
and loader machine bodies are not archived, and the trace excludes BLAS and
startup despite their static listing being present. Memory accesses, unmasked
exceptions, arbitrary inputs, full-process equivalence, Android/Bionic,
physical MIRO A1 execution, an executable EMC translation and ICK/NDK qualification
are not established by this result. This one-off research experiment uses its
own artifact and execution checks; no additional routing gate is invented.
